# Hoshii — site

Static marketing site: 17 pages, one stylesheet, no runtime dependencies.

**Sixteen of the seventeen pages are generated.** `tools/gen-legal.py` holds their
copy and emits the HTML. Editing those files by hand works until the next build,
which silently overwrites it. `index.html` and `styles.css` are the only files
written directly.

```bash
python3 tools/gen-legal.py      # rebuild the 16 generated pages + sitemap + robots
python3 tools/check-chrome.py   # fail if index.html has drifted from the generator
python3 tools/check-links.py    # fail if any internal link is broken or relative
python3 -m http.server 4321     # then open http://localhost:4321/
```

All three checks run in CI on every push, so a build that does not match what is
committed fails there rather than reaching the site.

## URLs

Every page is a directory index: `pricing/index.html`, served at `/pricing/`.
No `.html` in any URL, which matches the shape the Framer site serves and needs
no server configuration to do it.

**Internal links are root-relative, always** (`/pricing/`, `/assets/img/x.jpg`).
This is the opposite of the old rule and the reason is specific: with
extensionless URLs, `/policies/imprint` and `/policies/imprint/` have different
base directories, so one relative `../privacy-policy/` resolves to two
different places depending on whether the visitor's URL carried a trailing
slash. An absolute path cannot be read two ways. `tools/check-links.py` fails
the build on any relative internal link.

Templates and content still *write* paths relatively, against the folder the
page's content was authored for. `clean_urls` in the generator resolves them to
absolute form at build time, so there is one place that knows the layout.

## What is generated, and what is not

| | Files |
| --- | --- |
| Generated by `gen-legal.py` | the five `policies/*/`, the three `customers/*/`, plus `faq/`, `demo/`, `about/`, `partners/`, `careers/`, `resources/`, `customers/`, `pricing/`, and `sitemap.xml` + `robots.txt` |
| Hand-written | `index.html`, `styles.css`, `.htaccess` |

The generator also rewrites `index.html`'s canonical, `og:url` and robots meta,
so the origin switch below covers all seventeen pages rather than sixteen.

Content lives as heredoc strings near the bottom of the script in a small
line-oriented markup: `P:`, `H2:`, `H3:`, `LI:`, `TABLE:`/`ROW:`/`ENDTABLE:`,
`PLAN:`, `CLOSER:`, and `[text](url)` for links. Bare `<` or `>` and loose
ampersands are rejected rather than escaped, on the grounds that in this content
they are always an authoring slip.

`tools/gen-pattern.py` is separate and rarely run: it regenerates
`assets/pattern.svg`.

## Origin and staging

Canonicals, `og:url` and the sitemap all follow one origin, which is a flag
rather than a constant so the same build can go up on a staging host first:

```bash
python3 tools/gen-legal.py                                    # live: www.hoshii.ai
python3 tools/gen-legal.py --origin https://staging.example --staging
```

`--staging` puts `noindex, nofollow` on all seventeen pages and replaces
`robots.txt` with a blanket disallow. **Use it for every host that is not the
real domain.** A crawlable staging copy competes with the live site for the same
content, and the crawler decides which one wins, not you.

Switching back is one command and leaves no residue; both modes are idempotent.

## Deploying

Hostinger's Git integration pulls the repository into `public_html` on push and
**runs no build step** — what is committed is what is served. Two consequences:

- The generated HTML must be committed and in sync. That is what the CI check is
  for.
- Everything in the repo is web-reachable unless denied. `.htaccess` denies
  `tools/`, `.github/`, `README.md` and the dotfiles, because `gen-legal.py`
  carries every page's copy and notes on what was held back from pricing.

`.htaccess` also handles HTTPS, cache headers, compression, `.html` to directory
301s, and `/policies/` (a container with no index page). Two sections are
deliberately left commented for cutover day: the canonical-host redirect, and
the 301s from the Framer URLs this site does not replace. Read the comments
there before pointing a real domain at it. There is no `ErrorDocument` because
there is no 404 page yet.

**There is no GitHub Pages deploy any more.** Root-relative URLs cannot work on
a subpath, and Pages serves the repo from `/hoshii-site/`. The workflow in
`.github/workflows/` now only verifies the build.

Caching while developing locally, because `http.server` sends no cache headers:
`styles.css` is versioned in the markup (`styles.css?v=NN`) — bump `CSS_V` in the
generator and the copy in `index.html` together, which `check-chrome.py` now
enforces. `index.html` itself caches hard; load `index.html?r=N` with a fresh
number. Images cache by filename, so renaming is the reliable bust.

## Things that are load-bearing

**Guide lines.** `.guides` draws a 1px rule down each edge of a band's column
plus a hairline where bands meet. Each band sets its own `--guide-col`, so the
rules step inward down the page. A band's rules sit *on* its edges; text bands
inset their content from the rules, because type clamped to a line reads like a
mistake.

**`NOINDEX` pages are excluded from the sitemap by construction.** `msa` and
`sls` need stable URLs because order forms link to them, but they are not part of
the site: no footer link, no sitemap entry, and a robots meta to match. Listing
them would contradict the meta.

**Two customer stories have no page on purpose.** `CASE_MARINELLO` and
`CASE_ADANK_DAVOS` are defined but not in `DOCS`: their Framer Content field is
empty, so a page could only repeat the headline. Both play on the customers
index instead.
